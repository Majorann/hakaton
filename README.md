# Прозрачная вакансия

Локальный прототип для редактора вакансий. Он проверяет, достаточно ли ясно описаны условия работы, и формулирует вопросы, которые редактор может задать работодателю. Источник рабочего режима — открытый API портала «Работа России» для Калининградской области, регион 39. [Документация API](https://trudvsem.ru/opendata/api)

Программа работает в браузере, из командной строки и по расписанию. Анализ выполняет локальная модель через Ollama. Итоговый результат сохраняется в JSON.

## Быстрый старт на Windows

1. Скачайте репозиторий. Если скачали ZIP, распакуйте его и откройте папку проекта.
2. Один раз запустите [setup.bat](setup.bat). Он проверит Python 3.11 или новее и Ollama, предложит установить недостающие компоненты, предложит выбрать установленную локальную модель или скачать `qwen3.5:4b`, сохранит выбор и проверит ответ модели и запуск сервера. Установка компонентов требует подтверждения. Если открылся официальный сайт, завершите установку и снова запустите `setup.bat`.
3. Для повседневной работы открывайте [start.bat](start.bat). Он проверит Ollama и выбранную модель, дождётся локального сервера и откроет ссылку доступа в браузере по умолчанию. Повторный запуск использует уже работающий сервер, запущенный этими сценариями.

После обновления кода остановите прежний процесс `vacancy_web.py` и снова запустите `start.bat`. Ссылка доступа меняется при перезапуске сервера.

Проект использует стандартную библиотеку **Python 3.11 или новее** и локальную **Ollama** на `127.0.0.1:11434`. Интернет нужен для установки компонентов, скачивания модели и загрузки вакансий с портала. Проверка сохранённого JSON после настройки работает без интернета, аккаунта и API-ключа. Проект проверялся с Python 3.12 и Ollama 0.40.18 на Windows.

### Проверочный запуск

Перетащите исходный JSON на [verify.bat](verify.bat) или откройте BAT-файл и выберите JSON в диалоге. Подойдёт [пример входного файла](examples/api-response.json) или другой сохранённый ответ API. После проверки путь к отчёту появится в окне. По умолчанию это `output/verification-report.json`. Сервер веб-интерфейса для этого запуска не нужен.

Тот же файл можно проверить в браузере. В списке источников выберите **«Локальный JSON»**, затем нажмите **«Выбрать JSON»**.

## Работа в браузере

| Действие | Что происходит |
| --- | --- |
| **Загрузить с портала** | Один раз пополняет очередь «На разбор» до лимита. |
| **Локальный JSON** | Проверочный режим для сохранённого ответа API. Кнопка «Выбрать JSON» видна в этом режиме. Максимальный размер файла — 16 МБ, максимум 1000 записей. Уникальные вакансии проверяются без запросов к порталу. |
| **Автопоток** | Поддерживает лимит очереди «На разбор», пока включён, и ищет замену после архивации. |
| **Рекомендации отправлены** | Отмечает отправку работодателю и переносит вакансию с портала из очереди в архив. При включённом отслеживании можно запланировать повторные проверки карточки. |
| **Разобрано** | В режиме «Локальный JSON» убирает карточку из очереди. Отметка хранится в браузере. |
| **Скачать JSON** | Скачивает последний сохранённый отчёт выбранного режима. |

Полученные вакансии появляются в списке **«Текущая обработка»**, который открывается кнопкой в шапке во время работы, после загрузки каждой страницы или чтения файла. Отдельно формируется очередь для редактора. Карточка попадает туда сразу после проверки, если у вакансии есть замечания. Пока Qwen проверяет следующие вакансии, редактор может открыть готовую карточку, отфильтровать очередь по теме и скопировать вопрос работодателю. Текущая карточка остаётся открытой при появлении новых результатов.

Пока автопоток работает, очередь использует последний сохранённый отчёт и добавляет вакансии по мере проверки.

По завершении отображается итог проверки с числом результатов из кеша и новых вакансий с замечаниями. В **«Последней обработке»** остаются обработанные карточки и их статусы.

В настройках задайте число карточек в очереди **«На разбор»**. Поиск сохраняет карточки, которые уже ждут разбора, пропускает сохранённые и архивные ID и добавляет вакансии с замечаниями до заполнения очереди. Например, если лимит 20 и редактор архивирует одну карточку, включённый автопоток ищет одну замену. Если в выборке не хватает подходящих вакансий или проверка завершилась ошибкой, автопоток повторит поиск через 15 минут. Переключатель остаётся включённым при полной очереди. После перезапуска веб-сервера автопоток нужно включить снова.

В карточке показаны тип замечания, исходное поле, цитата, объяснение и вопрос работодателю. При противоречии приводятся оба исходных значения. Дословные фрагменты, которые помогают увидеть расхождение, могут быть подсвечены в цитате и объяснении. При пополнении в очередь добавляются только новые вакансии с замечаниями. При разовой проверке выборки из CLI или проверке локального файла сохраняются также вакансии с пустым массивом `findings`.

Если проблема в карточке определена неверно, нажмите значок флажка в её заголовке и при необходимости добавьте комментарий. Жалоба сохраняется отдельным JSON-файлом в папке `complaints` рядом с рабочим отчётом (по умолчанию `output/complaints/`). В файле находятся дата, источник, комментарий и снимок заявки с замечаниями. Жалоба не меняет статус заявки.

### Отслеживание исправлений

1. Включите **«Отслеживать исправления»** в настройках и выберите интервал. По умолчанию функция выключена, а интервал составляет 24 часа. Для демонстрации доступна 1 минута.
2. После отправки вопросов работодателю нажмите **«Рекомендации отправлены»**. Карточка попадёт в **«Архив»**. Снимите галочку в карточке перед отметкой, если её нужно архивировать без повторных проверок.
3. Через выбранный интервал сервер запросит карточку по ID вакансии и коду работодателя. Если поля, которые анализирует модель, совпадают с предыдущей версией, сервер обновит дату проверки. Если поля изменились, он запустит Ollama и сравнит замечания по темам. Если в старом отчёте нет отпечатка анализируемых полей, первая повторная проверка использует Ollama, чтобы получить актуальную точку сравнения.
4. В переключателе разделов выберите **«Все архивные»** или отфильтруйте архив по статусу. Переключатель доступен при включённом отслеживании. В архиве остаются исходные замечания и история изменений. Если API подтверждает отсутствие карточки, статус будет **«Недоступна на портале»**. При временной ошибке API или Ollama статус сохраняется, сервер повторит попытку.

Архив сохраняется в `output/report.json.archive.json` при стандартной конфигурации. Браузер можно закрыть. Когда локальный сервер снова запустится, он подхватит просроченные проверки. Отключение функции приостанавливает запланированные проверки. Текущая проверка может завершиться, а существующий архив сохранится.

## Командная строка и расписание

Выполняйте команды из папки проекта.

Для ручного запуска подготовьте Ollama командой `ollama pull qwen3.5:4b`, запустите `python vacancy_web.py` и откройте ссылку доступа из его консоли. После перезапуска сервера понадобится новая ссылка.

| Режим | Команда | Отчёт по умолчанию |
| --- | --- | --- |
| Проверить сохранённый ответ API | `python vacancy_report.py file examples/api-response.json` | `output/verification-report.json` |
| Получить вакансии с портала | `python vacancy_report.py api` | `output/report.json` |

Флаги `--config`, `--output` и `--log-file` указываются перед режимом. Первая команда сохраняет отдельный отчёт и журнал.

```powershell
python vacancy_report.py --output output/check.json --log-file output/check.log file examples/api-response.json
python vacancy_report.py --help
```

Веб-сервер принимает `--port` и `--config`. При смене путей к отчётам в конфигурации перезапустите веб-сервер. Отчёты, обновлённые командой или планировщиком, автоматически подхватываются открытой страницей. Чтобы разовый прогон из CLI сохранился отдельно от рабочего отчёта веб-интерфейса, укажите другой путь через `--output`.

### Ежедневный запуск на Windows

В [schedule.psd1](schedule.psd1) заданы имя задачи `TransparentVacancy` и время `09:00` по местному времени компьютера. Проверьте пути и команду в предпросмотре, затем зарегистрируйте задачу.

```powershell
./register-schedule.ps1 -Preview | Format-List
./register-schedule.ps1
```

Задача вызывает `vacancy_report.py api` и пишет журнал в `output/schedule.log`. Для запуска нужны активный сеанс пользователя и работающая Ollama. Проверочный запуск можно выполнить вручную из Планировщика заданий Windows. Чтобы изменить время, обновите `DailyAt` и выполните `./register-schedule.ps1 -Replace`.

## Настройки

В шапке интерфейса есть кнопка **«Настройки»**. Настройки записываются в [config.toml](config.toml). Новый лимит и основная модель применяются со следующего запуска, в том числе из командной строки и по расписанию.

| Ключ | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `api.url` | API региона 39 | HTTPS-адрес на `opendata.trudvsem.ru`. В старых копиях конфигурации замените `http://` на `https://`. |
| `api.max_vacancies` | `20` | Целевой размер очереди в веб-интерфейсе или лимит вакансий при рабочем запуске из CLI. Допустимо от 1 до 1000. |
| `api.page_size` | `10` | Число вакансий на странице API. При пополнении очереди количество страниц зависит от числа подходящих вакансий. |
| `api.timeout_seconds` | `20` | Тайм-аут запроса к порталу. |
| `ollama.model` | `qwen3.5:4b` | Локальная модель. В интерфейсе доступны установленные модели Ollama. |
| `ollama.timeout_seconds` | `180` | Тайм-аут запроса к модели. |
| `ollama.archive_model` | `""` | Локальная модель для повторных проверок архива. Пустое значение использует текущую основную модель. |
| `output.path` / `output.file_path` | `output/report.json` / `output/verification-report.json` | Пути к отчётам относительно папки файла конфигурации. |
| `web.reminder_hours` | `24` | Напоминание об устаревшем рабочем отчёте при наличии вакансий для разбора. Доступны 12, 24, 72 часа и `0`, чтобы отключить напоминание. |
| `web.followup_enabled` | `false` | Запускать запланированные проверки архивированных вакансий с портала. |
| `web.followup_minutes` | `1440` | Интервал повторной проверки, в минутах. Доступны `1`, `60`, `1440` и `4320`. |

## Как работает анализ

1. **Получение данных.** Рабочий режим запрашивает страницы API по HTTPS, с проверкой сертификата и ограничением ответа до 4 МБ. Проверочный читает массив `results.vacancies`, где каждая запись обёрнута в `vacancy`. При повторе ID используется первая запись. Перед отправкой в Ollama программа проверяет объём текста вакансии.
2. **Анализ.** Python проверяет формализуемые случаи. Например, сравнивает минимальный стаж из текста и поля «Опыт работы» в месяцах, различает обязательный и желательный опыт и предлагает уточнить условие о стаже, если оно зависит от образования. Qwen предлагает вопросы и ищет дополнительные пропуски, неоднозначности и противоречия. В запрос входят относящиеся к проверке поля объявления. Телефоны, адреса электронной почты и контакты из отдельных служебных полей в модель не передаются.
3. **Проверка доказательств.** Программа сверяет темы, исходные поля и цитаты. Правила отсекают известные случаи совместимых условий. Полный рабочий день совместим со сменами и циклами 5/2 или 2/2. Дни и часы в поле квалификации могут стать отдельным замечанием по оформлению. Если после повторного запроса отдельное замечание всё ещё ссылается на неверную цитату, оно отклоняется с записью в журнал.
4. **Сохранение.** Новый JSON заменяет предыдущий только после завершения проверки. При ошибке остаётся последний успешный отчёт. CLI сообщает о сбое кодом выхода `1`.

Модель получает структурированный запрос со схемой JSON. Используются `think: false` и температура `0`. В объяснениях и вопросах названия полей выводятся по-русски, например «График работы» и «Требуемая квалификация». Технические ключи сохраняются в структурированных ссылках на источники для проверки цитат. Указанные дни и часы, например «5/2, 9:00–18:00», учитываются вместе с полем «График работы». Для замечаний, найденных по правилам, приложение использует заданные в коде вопросы. Сгенерированные моделью вопросы помечены как черновики для проверки редактором.

Рабочий режим сохраняет результаты по ID в `output/.report.json.cache/`. Кеш используется, если совпали входные поля, модель и версия анализа. После обновления промпта разовый запуск `vacancy_report.py api` заново проверяет вакансии из своей выборки. При пополнении веб-очереди программа пропускает ID из отчёта и архива. Возраст публикации сам по себе не влияет на отбор. Проверочный режим анализирует локальный файл заново.

Повторная проверка архива работает для карточек со включённым отслеживанием в статусе «Ожидает исправления» или «Частично исправлена». Карточки без отметки об отправке остаются в обычной очереди. Если поля для анализа совпали с предыдущей версией, повторная проверка архива обновит дату без запуска Ollama.

При включённом отслеживании в настройках можно выбрать модель для **«Второго агента для архива»**. Подходит любая установленная локальная модель Ollama, в том числе основная. Она анализирует изменившиеся вакансии из архива, а её имя отображается в истории проверок. Выбранная модель закрепляется за архивом. При выборе **«Нет»** архив использует текущую основную модель.

## Формат отчёта

В корне JSON есть `model`, `source` (`api` или `file`), `completed_at` (время завершения в UTC) и `vacancies`. У каждой вакансии есть `id`, `title` и `url` при наличии в источнике, а также `findings`. Рабочий отчёт также содержит `content_hash` и `company_code`, если код работодателя получен из данных или ссылки. Если замечаний нет, `findings` — пустой массив.

| Поле замечания | Содержание |
| --- | --- |
| `topic` | `title`, `duties`, `requirements`, `pay`, `schedule`, `location` или `employment`. |
| `kind` | `missing` — пропуск, `ambiguous` — неоднозначность, `contradiction` — противоречие. |
| `evidence` | Список исходных полей `field` и значений `value`. Для пропуска значение пустое. Для противоречия указаны два источника и, при наличии, проверенный дословный фрагмент `highlight` для мягкой подсветки. |
| `problem_highlight` | Дословный фрагмент объяснения, который подсвечивается в карточке при наличии. |
| `problem` | Краткое объяснение проблемы. |
| `recommendation` | Вопрос или рекомендация для уточнения у работодателя. |
| `recommendation_source` | `rule` — вопрос из правила, `model` — черновик модели. В старых отчётах поле может отсутствовать, и интерфейс показывает такие вопросы как черновики. |

[Пример входных данных](examples/api-response.json) содержит четыре вакансии из реального ответа API региона 39. В нём сохранена структура API и удалены контактные и служебные поля, которые не нужны для проверки примера. [Сохранённый пример отчёта](examples/report.json) использует исходную версию формата. Новые отчёты дополнительно содержат режим запуска и время завершения.

Браузер запускает разовое пополнение через `POST /api/runs/api`, автопоток через `POST /api/runs/api/auto` и проверку локального файла через `POST /api/runs/file`. Состояние доступно через `GET /api/state`, отчёт через `GET /api/reports/{mode}`. Для управления текущей работой используются `POST /api/queue/pause` и `POST /api/queue/resume`. Настройки читаются и сохраняются через `GET /api/settings` и `POST /api/settings`. Для архива используются `GET /api/archive` и `POST /api/archive`. Сервер слушает локальный адрес `127.0.0.1`. Запросы к API требуют заголовок `Authorization: Bearer <токен>` из ссылки доступа текущего запуска.

## Проверка и демонстрация

1. **Проверочный режим.** Запустите команду с `examples/api-response.json`. В отчёте должны быть четыре уникальных ID. Для проверки содержания сопоставьте вопрос о гибком графике повара-кассира и два источника о стаже помощника воспитателя.
2. **Рабочий режим.** При доступном портале и достаточном количестве вакансий проверьте в журнале две страницы на стандартных настройках. При повторном запуске в одном отчёте должен остаться один результат на ID.
3. **Очередь в браузере.** Включите «Автопоток» и дождитесь заполнения очереди. Нажмите «Рекомендации отправлены» в одной карточке и проверьте, что она уходит в архив, а автопоток ищет замену до лимита. Повторите при выключенном автопотоке и запустите разовое пополнение кнопкой «Загрузить с портала».
4. **Обработка сбоя.** В копии конфигурации укажите адрес портала с `http://`, запустите `api` с этой копией и укажите через `--output` путь к отдельной копии успешного отчёта. Сравните копию до и после ошибки. В журнале должна быть ошибка, содержимое отчёта должно совпасть.
5. **Расписание.** Запустите `register-schedule.ps1 -Preview` и проверьте время, интерпретатор и путь к журналу.

### Локальный аудит 100 вакансий

На сохранённой последовательной выборке из 100 вакансий Калининградской области повторный прогон устранил 10 известных ложных противоречий по графику и выявил все 9 ранее отмеченных пропусков. Итоговый отчёт содержит 98 замечаний в 80 вакансиях. Эти цифры относятся к данной выборке и не оценивают точность на всех вакансиях.

Для повторения на сохранённой выборке с именем `output/audit-100-source.json` используйте отдельный выходной файл.

```powershell
python vacancy_report.py --output output/audit-100-repeat.json --log-file output/audit-100-repeat.log file output/audit-100-source.json
```

Исходный снимок, результаты аудита, рабочие отчёты, архив, журналы и кеш хранятся локально. Git игнорирует каталог `output/`, а примеры для запуска входят в [examples/](examples/).

## Если запуск не удался

| Симптом | Что проверить |
| --- | --- |
| Ошибка подключения к Ollama | Запущена ли Ollama и видна ли выбранная модель в `ollama list`. |
| Ошибка «нет массива results.vacancies» | Выбран ли исходный ответ API. Готовый отчёт имеет другой формат. Для проверки используйте входной файл из `examples/`. |
| Тайм-аут портала | Запустите проверочный режим на сохранённом ответе. Последний успешный рабочий отчёт остаётся доступен. |
| Сервер не запускается на порту 8765 | Если сервер уже запущен вручную, используйте ссылку из его консоли. Для отдельного ручного запуска выберите свободный порт, например `python vacancy_web.py --port 8766`. |
